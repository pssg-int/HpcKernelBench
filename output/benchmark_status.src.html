HPC-KernelBench Status

A kernel-optimization benchmark for HPC. From 7029 main-track papers published since 2020 at 10 conferences and journals we selected 917 kernel-optimization papers, 308 of which have an open-source artifact, normalized into 91 kernel groups. Executable specifications (spec.yaml) exist for 93 tracks; 35 of them have a runnable reference implementation and a correctness gate in the harness, and 29 tracks have paper artifacts integrated as baselines. Each track below lists what problem is computed, what the inputs are, how timing and correctness are judged, which baseline papers exist, and whether they reproduce and pass the gate under our harness.

Every "gated" result is a functional check on a login node (shared A100, synthetic smoke inputs, reduced protocol); the harness marks all of them conforming:false. No formal timing on compute nodes has been done yet.

H100 (sm_90) baselines (how this A100-era code behaves on Hopper): each integrated artifact was also gated on an H100. The key finding — old sm_80 binaries that embedded PTX run unchanged (JIT-forward), but SASS-only ones fail with cudaErrorNoKernelImageForDevice and only run once recompiled for sm_90. Per artifact below, an H100 PASS / recompiled / regression row shows the H100 outcome plus indicative throughput (smoke and, for the sparse/graph/ANN/tensor subset, real datasets — SuiteSparse, SNAP graphs, SIFT1M, FROSTT). Still indicative, conforming:false (clocks not lockable). Full write-up: bench/H100_baselines.md.

How the harness decides "reproduced"

Each track's spec.yaml is parsed and enforced at run time; it is not documentation. Preprocessing (format conversion, index construction) is timed once and separately; the correctness gate runs before timing, and a failed gate yields no throughput number; warmup iterations are discarded; every iteration gets its own pair of timestamps; median plus min/max/stdev are reported. Numerical gates use the componentwise backward-error scale |out−ref| / (|A|·|B|); structural gates compare sets, levels or scores exactly. The reference implementation never shares code objects with the implementation under test.

Artifact integration contract (bench/ARTIFACT_GUIDE.md): wrap the kernel, not the paper's benchmarking script; the artifact's own format conversion counts as preprocessing; patches are minimal and recorded one by one, only build-system changes are allowed, and an artifact whose kernel code must be edited to run is marked SKIP; the gate is never loosened, and a failed gate is a result; unsupported shapes must raise NotImplementedError, which the runner records as unsupported instead of crashing. Current scope: a single NVIDIA GPU; CPU-only, multi-GPU-only and FPGA artifacts are skipped with a documented reason.

Baseline selection rule (revised 2026-09-05): the early rule, "the 3 newest open-source artifacts per track", picked DSLs, LLM weight-sparsity kernels with a different input regime, and CPU implementations as SpMM baselines. Every (paper, track) pair now carries a kernel-centrality label: core the kernel is the paper's main contribution and is evaluated at the kernel level; component the kernel is part of a larger system, evaluated end-to-end, or generated by a compiler; tangential the kernel is merely called along the way. Added to this are regime match (whether the paper's evaluation inputs are of the same kind as the spec's input set) and single-GPU availability: core first, matching regime first, year only as a tiebreak. Adapters already integrated that fail the rule are kept as competitors but are not used as the Phase 3 "human SOTA" baseline.

Status meanings: GATED built and passed our correctness gate; GATE FAILS built but fails the gate (mostly bugs in the artifact itself, with evidence in STATUS.md); BUILT built, but the gate is blocked by the precision policy or cannot be verified independently; BUILD FAILED does not build with this machine's toolchain; SKIPPED skipped with a documented reason (kernel not implemented, platform out of scope, inseparable fused operator, …); DEFERRED (needs sm_90+) the only obstacle is the GPU architecture (Hopper-only PTX, FP8, …); source and provenance are kept for integration on a newer machine, and each directory's REQUIRES_GPU states the requirement.

Real findings from integration

These are problems exposed by putting paper artifacts into a unified harness. Each is recorded in the corresponding STATUS.md; the released source was not modified.

  • Split_SpTRSV (TPDS'21): two __threadfence calls in the synchronization-free executor are commented out, so the cross-block ready flag becomes visible before the data; matrices with ≥256 rows produce wrong results. A scratch build with the fences restored passes every gate at 1e-15.
  • PackKV (IPDPS'26): the kq kernel supports only hidden_dim ∈ {1024, 5120}; other shapes print "no such case", return 0 without an error, and the output is zero-initialized garbage.
  • STOF (PPoPP'26): the fine-grained mask inner_bitmaps is threaded through every signature but never dereferenced, so mixed tiles are silently computed as dense; the sliding-window gate rejects with err=6.83.
  • ZipServ: uint8 underflow in decompression plus integer promotion flips the sign bit; its self-check uses only GEMM cosine similarity and cannot catch it. MANS: illegal memory access on general byte streams.
  • LOGAN (IPDPS'20): kernel macros hardcode match=+1/mismatch=-1/gap=-1, so the run-time scoring parameters have no effect; the direction parameter is dead code and extension is always bidirectional.
  • Hidet fp32 convolution silently runs in TF32 (a 1×1 conv is rejected by the gate at 1.007e-3 against a 1e-3 bound). FlashFFTStencil is actually fp64 DMMA, not fp16. MetaAttention bidirectional attention is numerically wrong.
  • Ocean never writes the trailing CSR sentinel; Popcorn's SpGEMM is a = delete dead stub; MaxK-GNN's custom kernel has no Python binding and is never called by the training pipeline; StraGCN hardcodes the dense stride, so odd feature dimensions are silently miscomputed.
  • GroupTC assumes degree-ordered relabeling and otherwise counts exactly half the triangles; GridSelect silently returns wrong results for k>2048; Mille-feuille ignores maxiter and divides time by the literal 100; SPCG's "Convergence OK" is always true.
  • Quantix (PPoPP'26): the build references 3 non-existent files and the only quantization routine is debug placeholder code; qfactory silently outputs garbage for small group-size shapes; Bit-GraphBLAS's public artifact does not contain the BFS described in the paper.
  • BLCO frees uninitialized pointers and never zeroes its atomicAdd output. BootCMatchGX exports the solution vector with %g, i.e. 6 significant digits, so any independent residual check stalls near 1e-6 (passes the gate after changing to %.17g).
  • TurboFFT (PPoPP'25): the repository scripts never invoke the real code generator, so a direct build always fails; after running the generator, the unmodified headers compile completely. cuFalcon's "FFT" is negacyclic ring evaluation, not a DFT.
  • ExaGeoStat/Chameleon: dpotrf/dgemm residual 4.5 on the GPU path vs 4e-15 on CPU, a real GPU numerical bug. Fringe-SGC: a static accumulator is never reset, and the architecture can only express K4.
  • All three cg-krylov artifacts (SPCG, Mille-feuille, PERKS) genuinely stagnate without converging on cant; the gate rejects them, cross-checked against the scipy reference. This confirms the design point that "fast but not converged does not pass".

Environment and toolchain notes

  • The login node's default module drifted from cudatoolkit/12.9 to 13.2 while the harness's torch is cu128: the runner pins CUDA_HOME / PATH / CPATH / LIBRARY_PATH to 12.9 and its math_libs at start-up; every build script runs source bench/artifacts/toolchain.sh.
  • torch CUDA extensions need LD_PRELOAD=/usr/lib64/libstdc++.so.6 at run time (CXXABI_1.3.15). Cray MPICH has no mpirun; a single rank executed directly is an MPI singleton. The CUDA 12.9 SDK has no libnvToolsExt.so.
  • Artifact clones (87, over 5 GB) are not in git; each directory has a source.provenance (remote, commit, re-clone command) and a source.patch when tracked files were modified.
